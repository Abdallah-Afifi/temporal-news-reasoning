## A. `AUG_NOANS` teaches a shortcut (real defect, disclose)

In v6's mixture, an abstain-phrased option appears as a **wrong** option in
the answerable rows **0 times** (500 `AUG_NOANS` vs 1,999 `AUG_MCQ`/`AUG_MCQ2`
rows). So the mixture is perfectly separable on surface form: *an option
phrased as an abstention is always the correct one.* **This is structurally
the same defect as `AUG_NLI`'s label leakage** (every `Neutral` identifiable
from the word "another", 67.1% vs 33.3% chance), which cost a cycle.

**Fix for v7:** have `build_noans_and_mcq` inject an abstain-phrased option as
a **distractor** in a fraction of the answerable rows, so the cue is broken.
Not applied to v6 — it is already training.

## B. TIME cannot punish that shortcut — and this revises the v6 forecast

| | count |
|---|---|
| TIME answerable-MCQ items | 46,937 |
| ...that offer an abstain option as a **distractor** | **0** |
| TIME no-answer items (abstain option **is** the gold) | 2,427 |

**In TIME, an abstain option is offered only when it is the correct answer.**
Two consequences:

1. **The over-abstention risk to v6 is far lower than forecast.** The model
   cannot lose answerable items by wrongly selecting an abstain option,
   because none is offered. The `MCQ: answerable` estimate of 63.5% (which
   priced in over-abstention) should be revised toward v5's **64.50%**, and
   v6's TIME estimate from ~41.2% toward **~41.7%**. Residual risk is only
   that v6 emits abstain text as a *free-text* answer where no such option
   exists — visible in the probe's `free text` row.
2. **A benchmark defect worth disclosing.** Those 2,427 items are solvable by
   pattern-matching ("an abstain option is present, so it is the answer") with
   **no temporal reasoning at all**. Zero-shot scores only 52.95%, so it is
   *not* exploiting it — but if v6 scores near 100% there, **that gain is
   benchmark-artifact exploitation, not capability, and must be reported as
   such.**

Also found: TIME's abstain gold is punctuated inconsistently — both
`"There is no answer"` and `"There is no answer."` occur. The probe's regex
handles it; exact-match analyses would not.

## E. Today's trailing-letter rule destroyed 143 correct answers (fixed)

The rule as first written was described as "purely additive — it cannot change
any decision the existing rules already made." **That is true of rule
precedence and false of scoring outcomes:** where the function previously
returned raw text, that raw text could already have been scoring correct.

| arm | fires | gained | **lost** | net |
|---|---|---|---|---|
| v2-ft | 40,711 | 5,146 | **15** | +5,131 |
| v3-corr | 4,305 | 1,549 | **114** | +1,435 |
| v4 | 9,013 | 2,628 | 11 | +2,617 |
| v5 | 23,283 | 1,925 | 3 | +1,922 |

**Root cause:** some TIME golds are **space**-separated letter sequences
(`"A C"`, `"A B C"`). The model answers `"A; C"`, which normalises to the gold
and scored correct — until the rule read the stem `"A"` and the letter `"C"`
and resolved it to an option.

**Fix:** a `_LETTERS_ONLY_RE` guard — if the stem is nothing but option letters
and separators, the semicolons are separators, not a self-declaration.
Losses **143 → 7** with gains preserved. Two tests added.

## F. The gold-shape taxonomy was incomplete — **FIXED**

Every bucket analysis today classified golds as *comma-separated letter
sequence / bare letter / paren permutation / free text*. It missed
**space-separated letter sequences** (`"A C"`): **2,614 items, 2.49% of
TIME**, which were counted as **free text**. The free-text bucket is therefore
~2.5pp smaller than reported and mildly heterogeneous. This does not change
any arm-to-arm comparison (the same items are in the same bucket for every
arm), but it mattered urgently for one reason: **`probe_answer_formats.py` —
the tool v6's result will be read with — used the comma-only pattern, and its
`emitted()` check for the free-text bucket only tests for non-empty output. A
total collapse on those 2,614 items would therefore have reported as 100%
emitted.**

**FIXED in this pass:** `SEQ` now accepts either separator. Corrected buckets:

| gold shape | n | share | zero-shot | v3-corr | v5 |
|---|---|---|---|---|---|
| MCQ answerable | 46,937 | 44.7% | 63.54% | 61.94% | **64.49%** |
| MCQ no-answer | 2,427 | 2.3% | 52.95% | 7.25% | 0.74% |
| **letter sequence** | **13,975** | **13.3%** | 15.48% | 13.46% | 0.00% |
| free text | 39,814 | 37.9% | 25.70% | 27.32% | 25.26% |
| paren permutation | 1,798 | 1.7% | 0.22% | 0.17% | 0.22% |

The sequence bucket is **13.3% of TIME, not 10.8%**, and zero-shot scores
**15.48%** there, not 19.05%. **The two corrections cancel** — the bucket's
contribution to v5's gap is −2.06pp either way — so v7's and v8's target
arithmetic is unchanged. Corrected leverage: MCQ answerable **0.45pp**/pp,
free text 0.38, letter sequence 0.13, no-answer 0.02. v5 also emits 3.11% on
the widened bucket (not 0.01%), i.e. it does produce some space-separated
sequences — all of them wrong.

## G. `matches_any` credited semantically opposite answers (fixed)

```
matches_any("the 1979 establishment of the Islamic Republic",
            ["the 1979 overthrow of the U.S.-backed monarchy"])  ->  True
```

The bare-year branch guarded only on **length** (`len(np_) >= len(nr) - 1`),
never on whether the non-date words agreed. Any two short prose strings
sharing a year matched.

**Measured inflation before the fix** — real, and it favoured **zero-shot**:

| arm | bare-year credits | ...content differs | inflation |
|---|---|---|---|
| zero-shot | 251 | **99** | **0.09pp** |
| v3-corr | 739 | 43 | 0.04pp |
| v4 | 485 | 14 | 0.01pp |
| v5 | 681 | 9 | 0.01pp |

**Fix:** at the bare-year level, require the non-year content-word sets to be
subsets either way — a reformatting may drop or add filler ("in 1945" vs
"1945") but may never *substitute* a content word. Test added.

## 13. Is the scoring change methodologically defensible? (asked 2026-09-07)

**Yes, conditionally — and one part of it is weaker than the other. Do not
conflate them.**

### The two corrections have very different standing

| correction | mechanism | standing |
|---|---|---|
| **date equivalence** | `18 March 1934` == `March 18, 1934` | **Unimpeachable.** Nobody disputes two spellings of a date denote the same date. Not an artifact of our data. |
| **trailing letter** | `Berlin; B` -> `Berlin` | **Defensible but vulnerable.** The `"; LETTER"` shape exists *because* `AUG_MCQ`'s dual-gold list is joined with `"; "` by our own loader. |

**Measured, v6 on TimeBench** (stored 43.93% -> protocol 47.18%, +3.26pp):

| source of the gain | items |
|---|---|
| postprocessor rewrite (the trailing-letter rule) | **0** |
| `matches_any` — date reformatting / dual-gold | **690** |

TimeBench contains no letter-sequence items, so the letter rule is inert
there: **v6's TimeBench gain is entirely the date rule.** Any claim that v6
gained "because the scorer can now read its letters" is wrong for TimeBench.

### Why the protocol is legitimate

1. **Identical code scores every arm.** Nothing is arm-specific.
2. **Zero-shot gains 0.00pp from the letter rule** — it never emits the shape,
   so it was never mis-measured and needs no help. That asymmetry is evidence
   of a *correction*, not a favour.
3. The pre-fix scorer was objectively wrong on those items.

### The genuine objection, stated plainly

*"You trained a nonstandard output format, then widened the scorer to accept
it."* This applies **only** to the trailing-letter rule, and it is fair. The
format is our artifact.

### The fix that removes the objection — required in v7

**Stop producing the format instead of accommodating it.** Give
`AUG_MCQ`/`AUG_MCQ2` a **single** target (option text only, not
`[text, LETTER]`). The model then answers in the benchmark's own expected
form, and the trailing-letter rule becomes inert.

**Pre-registered falsifiable check for v7:** build it with single-target MCQ,
then count how often `_TRAILING_LETTER_RE` fires on v7's predictions.
**If it fires ~0 times and v7 still scores well, the result is provably not an
artifact of the scoring change.** If it still fires often, the training data
is still teaching the shape and the objection stands.

### Thesis obligation either way

**Report BOTH columns — strict exact match and protocol — for every arm, in
every table.** `rescore_v5_protocol.py` already prints both. Showing only the
protocol column invites the goalpost accusation; showing both makes the
argument transparent and lets the reader check it.

### 13b. "If the rule is wrong, do we remove it even though it raises accuracy?"

**Yes — unconditionally, and direction is irrelevant.** This is not
hypothetical: on 2026-09-07 the bare-year fix (§ G) removed wrongly-credited
answers and **lowered every arm** — zero-shot −0.09pp, v3-corrected −0.04pp,
others −0.01pp. A rule that inflates is a bug and gets deleted.

**But the trailing-letter rule is not wrong.** The test to apply:

> Would a careful human grader, shown only the model's raw output and the
> gold, mark it correct?

| raw output | gold | grader | our scorer |
|---|---|---|---|
| `Berlin; B` | `Berlin` | correct — it names Berlin | credits |
| `18 March 1934` | `March 18, 1934` | correct — same date | credits |
| `the 1979 establishment` | `the 1979 overthrow` | **wrong** | **removed (§ G)** |
| `A` | `B,C,A` | wrong | never credited |

The rule parses an unambiguous answer; it does not invent one. **Under-
crediting is as much a measurement error as over-crediting** — scoring
`Berlin; B` wrong when the model plainly said Berlin is not conservatism, it
is a different bug. That is precisely what the *original* broken rule did
(any prediction starting with A-D was rewritten into that option, inventing
answers the model never gave), and it was correctly deleted.

**What IS wrong is upstream:** needing a custom parser at all, because our
loader joins `AUG_MCQ`'s dual gold into `"<text>; B"`. That is a training-data
design flaw, not a scorer flaw. v7 fixes the cause (§ 3b of `v7_plan.md`);
patching the scorer only treats the symptom.
