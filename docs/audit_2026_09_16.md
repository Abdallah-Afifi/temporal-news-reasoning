# Audit — 2026-09-16: the v9 synthetic arm (`AUG_GLM2`)

> **Numbers in §1–§5 below were measured on 2026-09-16 and some are wrong.**
> The article index was cached in a way that ignored my own fix to the corpus
> loader, so the page-furniture results in §1.3 describe data the filter had
> never touched. See **§7 Follow-up (2026-09-19)** for what was actually
> measured once that was corrected. The findings stand; three figures moved.

Scope: the v9 data-generation chain (`docs/synthetic_data_ruleset.md`,
`scripts/generate_v9_aug.py`, `scripts/v9/*`, `scripts/audit_v9_aug.py`,
`data/manual_aug_v9/`, `data/combined_80_20_v9/`,
`experiments/finetuning/LLaMA/config_v9.yaml`), plus a re-check of the
repository state left by the audits of 2026-09-14 and 2026-09-14b.

**Bottom line.** v9 had never been trained, so no GPU time was lost. The arm
was staged and ready to launch behind an acceptance report reading
`Overall: PASS`. That report was passing because of what it did not measure.
Three defect classes were invisible to it; all three are now gated, two are
fixed in the generator, and the arm is blocked pending one design decision.

## 1. What was actually wrong

### 1.1 The name is wrong — `AUG_GLM2` contains no model-generated text

`docs/synthetic_data_ruleset.md` is written as an instruction document for a
generating LLM, and `config_v9.yaml` described the rows as "LLM-grade". The
rows on disk were produced by **deterministic Python templates**
(`scripts/generate_v9_aug.py` → `scripts/v9/block_{a,b,c}.py`) filling slots
from a local CC-News snapshot. There is no API call anywhere on that path —
verified by grep across the whole generation chain.

This matters beyond tidiness. The ruleset justifies the arm by citing
`AUG_GLM` — 502 genuinely LLM-written rows that moved TIME `Counterfactual`
+13.1pp — and presents v9 as "that slice done at scale". A reader would
conclude v9 tests the same intervention. It does not. Template text has
different failure modes, and this audit found them.

Fixed: provenance banners in `docs/synthetic_data_ruleset.md` and
`config_v9.yaml`. The `AUG_GLM2` key itself was **not** renamed — it is baked
into manifests and build scripts, and a rename is a wider change than this
audit should make silently.

### 1.2 Contexts padded by verbatim repetition

`scripts/v9/ctxbuild.py` reached its target word count with

```python
while words < words_band[0]:
    pad = (f"{a}: Anything else you remember from that period?\n"
           f"{b}: Only that the reporting kept adding detail with each update.")
```

— one exchange, appended in a loop. **426 rows (7.1%) carried such a block,
including all 250 `temporal_dialogue` rows**, with a single line repeated up to
**76 times**. Two smaller variants of the same bug: a hardcoded post-event
aside repeated up to 14 times.

Training on this teaches degenerate repetition and spends the context budget on
nothing. Fixed: distinct filler pools, each exchange used at most once, and a
short context returned rather than padded (ruleset §8: report a shortfall,
never pad). **426 rows → 8 (0.13%)**; the gate now passes.

### 1.3 Golds truncated mid-clause and lifted from page furniture

`trim_sentence()` cut at 28 words and `clip()` took a raw word prefix; neither
checked what the fragment ended on. Result: **128 gold answers and 187 question
stems ended mid-clause** — `"...the submarine disappeared somewhere in."` —
a gold no model can produce and no scorer can match. Separately, the corpus
sentence filter passed bylines, nav text and newsletter prompts through, so
they became gold answers and MCQ options:

- gold: `"Photos Related Stories Literary farmers tell the story of China's..."`
- option: `"Please enter an answer in digits:2 × 1 = Post navigation Previous..."`

Fixed: `strip_dangling()` in `scripts/v9/common.py`, applied in both
`trim_sentence()` and `clip()`; a narrowed page-furniture filter in
`scripts/v9/corpus.py`. **Truncated golds 128 → 68.**

A first attempt at the furniture filter was case-folded and broader. It removed
ordinary prose containing "copyright" / "subscribe" / "published:", cut
`Co_temporality` to 266 of 300 rows, and — by stripping short distractors —
pushed the longest-option shortcut probe to 35%, failing a gate that had
passed. That version was reverted in favour of a narrow case-sensitive one.
Recorded because the failure mode is instructive: cleaning the distractor pool
can manufacture a shortcut.

### 1.4 The acceptance report asserted a manual review that never happened

`scripts/audit_v9_aug.py` printed the header

> `Manual-check samples (§7.4 protocol: 100 rows/category by eye)`

above a block that dumps `--sample-rows` rows per category — **default 3**, so
54 rows total — with no human verdict recorded anywhere. §7.4 requires 100 rows
per category reviewed by eye for each category whose golds cannot be
recomputed. **2,926 rows (49.0%)** are in such categories: `Counterfactual`,
`Relative_Reasoning`, `Localization`, `Order_Reasoning`, `Co_temporality`,
`temporal_dialogue`, `Explicit_Reasoning`, `longform_free`, `storytelling`,
`duration`. None of them had their golds checked by anything.

Fixed: the header now says what the block does and states explicitly that it is
not the §7.4 check.

### 1.5 No gate measured whether a row reads as a well-formed QA pair

This is the structural finding. §7.1–§7.4 gated contamination, distribution,
shortcuts and arithmetic — genuinely good gates, see §3 — but nothing measured
surface quality, so §1.2–§1.3 were free to pass. Added **§7.5 Surface quality**
to `scripts/audit_v9_aug.py`: answer style, degenerate padding, truncated and
boilerplate golds.

## 2. The open item — answer style (§9), a design decision

`AUG_GLM2` free-text golds average **7.88 words**; TIME's average **2.35**,
median 1. **14.1%** of v9 free-text golds run to 20 words or more against TIME's
**0.95%** — a fifteen-fold difference. `AUG_GLM2` is **39.8%** of the v9 train
mixture, so it sets the answer style the frozen scorer then has to match.

The ruleset's own §9 says "keep golds terse" and cites the 2.35 figure, giving
`diocesan bishop` as a typical `Co_temporality` gold. The generator emits 14.7
words for that category. So this is the generator diverging from its own spec,
not a considered choice.

MCQ golds are excluded from the gate: §9 requires them to be the option text
verbatim so exact match can fire, and that requirement is met — **2,533 of
2,533 non-`Timeline` MCQ golds are character-identical to an option**
(`Timeline`'s letter-sequence gold is the documented exception).

**Why this is not mechanically fixable.** Several Block A categories ask
questions that have no terse answer — `"While events around X were still
unfolding between 2001 and 2024, what was reported concerning X?"` has a
paragraph as its honest answer. Shortening the gold would not fix the row; the
question design is what generates the long gold. Choosing between (a) reshaping
those question templates toward answers TIME-style scoring can match and
(b) dropping the categories is a research-design call, and it changes what the
arm tests. **It is left to the researcher.**

## 3. What held up

Re-verified independently, not taken from the report:

- **Contamination: clean.** 0 exact and punctuation-insensitive question
  collisions against TIME; 0 rows sharing a 30-token shingle with any TIME
  context, checked against an index of **3,796,123** shingles built from
  103,151 benchmark contexts. The generator genuinely never sees benchmark
  files.
- **Date arithmetic: correct.** Four `Computation` date-shift golds recomputed
  by hand, all correct; the "N days after X" construction is sound.
- **Benchmark fidelity of the stem format.** I suspected the inline dates in
  `Computation` stems were a shortcut letting the model skip the context. They
  are not a v9 defect: **real TIME prints both endpoint dates in the stem in
  60.8%** of its own Computation items. The odd "How many days elapsed…" phrasing
  paired with a year/month answer hint is likewise copied faithfully from TIME.
- **Hyperparameter comparability.** `config_v9.yaml` is identical to
  `config_v6.yaml` outside `train_data`/`val_data`/`output_dir`, so the
  data-only-bundle claim holds.
- **Test suite.** 146 passed, 6 skipped, unchanged by this audit's edits.

## 4. Pre-existing issues, not v9-specific

- **Train/val context overlap.** 42.9% of v9 val rows share a context with a
  train row. Checkpoint selection runs on this set (`load_best_model_at_end`,
  `metric_for_best_model: eval_loss`, `early_stopping_patience: 2`), so
  `eval_loss` is optimistic and early stopping is less sensitive than it looks.
  This is **not a v9 regression** — v6 and v7-corrected are at **72.9%**, and v9
  improves on them. It affects every arm roughly equally, so cross-arm
  comparisons stand; it is a caveat on the absolute loss curves.
- **Stale v7 header in `config_v9.yaml`.** The file carried a full copy of v7's
  rationale block ("The MCQ / format arm…", "THREE data changes vs v6") below
  the v9 header, describing a different arm. Removed.
- **`data/combined_80_20_v9/` is now stale.** It was built from the pre-fix aug
  data. Marked with `STALE_DO_NOT_TRAIN.md`; rebuild only after §2 is resolved.

## 7. Follow-up — 2026-09-19

Re-checking this audit's own work turned up two defects in it, one of them the
same class of failure the audit was written to catch.

### 7.1 The corpus fix never reached the data (cache invalidation)

`scripts/generate_v9_aug.py` caches the parsed article index as
`data/.v9_cache/arts_{limit}_{ban}.pkl`. That key carries no component of the
loader's own code — and `_clean_sent()`, where §1.3's page-furniture filter
lives, runs at **load** time, so its output is exactly what gets pickled.

    data/.v9_cache/arts_all_0.pkl   12:27:15
    scripts/v9/corpus.py            12:36:05   <- the filter, nine minutes late

Every regeneration after that reloaded the stale index, so the filter was
inert. Measured by moving the cache aside and rescanning:

| | article pools | rows |
|---|---|---|
| stale cache (filter absent) | full2=3631, any2=28245 | 5,990 |
| fresh scan (filter applied) | full2=3561, any2=27611 | 5,930 |

So §1.3's boilerplate figures were reported against data the filter had not
touched. With it genuinely applied, boilerplate golds fall **25 → 14**; the
truncation figures are unaffected, because `strip_dangling()` runs at
generation time and did land.

**Fixed:** the cache key now includes a SHA-1 of `scripts/v9/corpus.py`, so
editing the loader invalidates the index automatically. This is the same
defect class as §1.4 — a stored artifact asserting a state it no longer had —
and it cost a fix that looked applied and was not.

### 7.2 The truncation fix broke a shortcut probe

`trim_sentence()` was changed in §1.3 to back off to a clause boundary
anywhere past the midpoint of its window. That cut distractors well short of
their 24-word budget. In `Relative_Reasoning` the gold is a paraphrase of a
full sentence and is **not** capped, so shorter distractors made the gold the
longest option in **30%** of rows against L7's 30% ceiling — a probe that had
passed at 18% before the change.

L7 is unambiguous that a slice failing a shortcut probe is worthless however
well it reads, so this mattered more than the defect it was introduced to fix.

**Fixed:** the clause boundary is taken only when it retains ≥80% of the word
budget. `Relative_Reasoning` longest-option is back to **20% (PASS)**.

### 7.3 The GLM validator would have rejected an entire category

`scripts/ingest_glm_batch.py` required a question mark on any row without a
Choices block. `nli_saq` rows are declarative premise/hypothesis statements
with neither — that is the category's entire purpose ("the model must emit the
bare token"). The check would have rejected **100% of that 400-row slice**.

Found by `tests/test_glm_ingest.py`, added in this pass: 24 tests covering the
schema rules, MCQ structure, label categories, §9 answer style, §5.1
copied-gold detection and §7.4 arithmetic — including the two arithmetic
errors and the two validator false positives the GLM pilot exposed. The
validator is the only thing between raw model output and a training mixture;
it should not have been shipped untested.

### 7.4 Current state of the template arm

`data/manual_aug_v9/` regenerated at **5,948 rows** with every fix genuinely
applied. `AUDIT.md` reports **OVERALL: FAIL** on three gates:

| gate | value | note |
|---|---|---|
| §9 answer style | mean 8.11 words, 14.8% ≥20w | the design issue of §2; unchanged |
| truncated / page-furniture golds | 79 + 14 (1.6%) | boilerplate improved 25 → 14 |
| Localization gold recomputation | 134/137 = 97.8% | 3 rows; fluctuates 99.3 → 97.8 run to run |

Padding and shortcut probes now pass. `data/combined_80_20_v9/` was rebuilt
from this set and is consistent with it.

### 7.5 The arm this supersedes

The researcher's decision on 2026-09-17 was to abandon template generation and
produce the slice with GLM instead, unseeded — no CC-News corpus, the model
writing its own passages in the §6 shapes. The pilot is the reason: GLM's
free-text golds averaged **4.00 words with 0% at ≥20**, against the template
set's 8.11 / 14.8% and TIME's 2.35 / 0.95%. That clears the §9 gate the
template generator could not.

`scripts/run_schedule_v9.sh` still points at `data/combined_80_20_v9`, i.e. the
**template** mixture. It must be repointed before it is launched, or it will
train the arm that was abandoned.
