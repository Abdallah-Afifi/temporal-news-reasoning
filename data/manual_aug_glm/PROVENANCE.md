# AUG_GLM2 corpus provenance (`data/glm_raw/001–313`) — 2026-10-05

Follow-up to `docs/audit_2026_10_04.md` §1.2. `AUDIT.md` (v9) says this
corpus was "Generated by GLM chat". This file checks that claim file by
file. Row counts come from `.ingested.json`: **5,298 ingested rows in 313
files**, and these rows feed v9-glm → v12 training data.

## Method

The original authoring environment (`/tmp/opencode`) is gone, so the
evidence is indirect:

1. **Builder references.** Every script still on disk that writes to
   `data/glm_raw/{fno}.txt` was checked (`scripts/glm_v13_build/*_lib.py`,
   `build_*.py`, `syn_gen.py`). Their literal file numbers cover exactly
   271–313:

   | Files | Builder |
   |---|---|
   | 271–277 | `build_nm*` (nli_mcq) |
   | 278–284 | `build_td*` (temporal_dialogue) |
   | 285–290 | `build_dc*` (Duration_Compare) |
   | 291–295 | `build_er*` (extract) |
   | 296, 297, 309 | `syn_gen` |
   | 298–301 | `build_st1` (storytelling) |
   | 302–308, 310–313 | `build_lf_oc`, `build_oc2` (longform / Order_Compare) |

   No surviving script references any file numbered 001–270.
   `run_glm_packets.py` (the GLM API route) can write here, but no API log
   or "saved N chars" trace exists.
2. **Write timing**, at nanosecond precision. Files are grouped when their
   mtimes chain within 1 s. A group of 2–6 files written within ≤50 ms
   ("ms-burst") was written by a single process — an agent's file-writing
   tool or a script, not a person saving pasted chat replies. The
   script-built files 271–313 have a median spread of 1.8 ms; bursts in
   001–270 have a median of 2.2 ms (max 70 ms).
3. **Passage templating.** For each file: the share of its word-only
   6-gram shingles (numbers and dates stripped) that also appear in ≥3
   other files. Slot-filled generators reuse skeletons heavily. Known v13
   template generators (`gen_reasoning/gen_rel/gen_dialogue/gen_stories`)
   score a median of **0.212**. glm_raw 271–313 scores **0.003** and
   001–270 scores **0.001**. So the 271–313 builders embed unique
   hand-written passages as string literals rather than slot-filling, and
   001–270 shows no template reuse either.

## Reading

- **No part of the corpus can be confirmed as GLM *chat-UI* output.** At
  least 83% of rows (4,412 of 5,298) were written by a process, not pasted
  by a person.
- **The text looks LLM-written, not slot-filled.** Shingle reuse is at the
  hand-written level everywhere, including 271–313. The likely author is
  the GLM-5.3 model acting as the opencode coding agent. That makes the
  rows GLM-authored in the sense of "written by a GLM model". It does not
  match `AUDIT.md`'s "GLM chat (MASTER_PROMPT.md, invented per-order)"
  workflow.
- **Files 271–313 also have programmatic structure.** Golds and options
  were assembled by builder code with fixed rotation (e.g. `er_lib.erow`
  with `[0,1,2,3][i%4]`). So they inherit builder-level regularities, such
  as letter position, even though the passages are unique.
- **v11 and v12 measured gains are unaffected.** They are measured on
  test, whatever the data's origin. What changes is how the data should
  be described: "GLM-model-authored via an agent, 15% assembled by
  builder scripts" — not "GLM chat".
